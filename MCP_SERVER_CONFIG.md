# Elite Agent Collective - MCP Server

> **Rewritten 2026-11-12.** The previous version of this file described an HTTP service with
> OIDC, Redis, PostgreSQL, rate limits and cloud deployments and called it an MCP server. No
> MCP code existed in this repository at the time: the document was a plan written as fact.
> This version describes only what `mcp_server/` does. The protocol, tool and error behaviour
> below is exercised by the tests in `mcp_server/tests/`; statements about other software are
> marked with where and when they were checked.

## What it is

A small [Model Context Protocol](https://modelcontextprotocol.io/) server that serves the 40
agent definitions in `.github/agents/*.agent.md` to an MCP client such as Claude Code.

- **Transport:** stdio only. JSON-RPC 2.0, one JSON message per line on stdin/stdout.
  Diagnostics go to stderr.
- **Code:** Python standard library only (`mcp_server/`, Python 3.10+). No MCP SDK, no
  third-party packages, nothing to install.
- **Network:** none. The server opens no sockets and calls no model, local or cloud.
- **State:** none. Definitions are read once at start-up; restart the server to pick up
  edited files.

## What it is not

- It is **not** the Go backend in `backend/`. That is a separate HTTP service for the GitHub
  Copilot Extension (`/health`, `/metrics`, `/agents`, `/agents/{codename}` and the Copilot
  chat routes, among others - see `backend/cmd/server/main.go` for the full list). The backend
  does not speak MCP.
- It does **not run agents**. `invoke_agent` returns the agent's prompt for the calling model
  to use; no answer is generated by this server.
- It has no HTTP or WebSocket transport, no authentication, no rate limiting, no memory
  system, no metrics and no container or cloud deployment. A stdio server is started by the
  client as a child process and inherits that client's trust.
- `find_agent` is **lexical**, not semantic: it ranks by word overlap with each definition.
- Tested on Python 3.14 only. The code uses nothing newer than 3.10 syntax, but no older
  interpreter has been run.

## Run it

From the repository root:

```bash
python -m mcp_server
```

It prints one line to stderr (`elite-agent-collective 0.1.0: 40 agents from ...`) and then
waits for JSON-RPC on stdin. It exits with code 0 when stdin closes, and with code 1 (message
on stderr, nothing on stdout) if the agents directory is missing or empty.

| Environment variable | Meaning | Default |
| --- | --- | --- |
| `AGENTS_DIR` | Directory holding the `*.agent.md` files | `.github/agents` of this repository |

### Register with an MCP client

The server must be importable, so point `PYTHONPATH` at the repository root. For Claude Code,
under `mcpServers`:

```json
"elite-agents": {
  "command": "python",
  "args": ["-m", "mcp_server"],
  "env": { "PYTHONPATH": "C:\\path\\to\\elite-agent-collective" }
}
```

## Protocol

| Method | Behaviour |
| --- | --- |
| `initialize` | Returns `serverInfo`, capabilities `tools` and `resources`, and a protocol version: the client's requested version if it is `2025-06-18`, `2025-03-26` or `2024-11-05`, otherwise `2025-06-18`. |
| `ping` | Returns `{}`. |
| `tools/list` | The four tools below. |
| `tools/call` | Runs a tool. |
| `resources/list` | `agents://roster` plus one `agents://<CODENAME>` per agent. |
| `resources/read` | The roster table or one agent's definition file, as `text/markdown`. |

Notifications (messages without an `id`, such as `notifications/initialized`) are accepted and
never answered. Requests other than `initialize` and `ping` are refused with `-32600` until
`initialize` has been called. JSON-RPC batches (arrays) are accepted.

Not implemented: prompts, sampling, logging, completions, resource subscriptions, list-changed
notifications, progress notifications, pagination and cancellation (every call returns at
once, so there is nothing to cancel).

### Tools

| Tool | Arguments | Returns |
| --- | --- | --- |
| `list_agents` | `tier` (integer, optional), `category` (substring, optional) | Markdown table; `structuredContent.agents` with name, tier, category, description. |
| `find_agent` | `task_description` (required), `limit` (1-10, default 3) | Agents ranked by word overlap with their definitions, with the words that matched. An empty list and a plain "nothing matched" message when no word overlaps - it does not fall back to a default agent. |
| `get_agent` | `name` (required) | The whole definition file (front matter and prompt). |
| `invoke_agent` | `name` (required), `task` (optional) | The agent's prompt (the file body without front matter), framed with the task, under a notice that no model was called. `structuredContent.executed` is always `false`. |

Agent names are case-insensitive and may carry a leading `@`.

### Errors

| Situation | Reported as |
| --- | --- |
| Line is not valid JSON | JSON-RPC error `-32700`, `id` null |
| Not a JSON-RPC 2.0 request, or sent before `initialize` | `-32600` |
| Unknown method | `-32601` |
| Unknown tool, missing/unknown/wrongly typed argument | `-32602` |
| Unknown resource URI | `-32002` |
| Bug inside a handler | `-32603` "Internal error" (details on stderr only) |
| Tool ran but failed (for example agent not found) | Normal result with `isError: true` |

No protocol error ends the session, including a line nested too deeply to parse (`-32700`).
Request ids must be strings or finite numbers; any other id is answered with `-32600` and a
`null` id, never echoed. `NaN`, `Infinity` and numbers too large for a float (`1e999`) are not
accepted anywhere in a message (`-32700`). `params` may be omitted or `null`.

## How `find_agent` ranks

The task is split into lower-case words; common English stopwords are dropped and a crude
suffix strip (`-ing`, `-ed`, `-es`, `-s`) is applied. Each agent is scored on the words it
shares with the task: a word found in the agent's front-matter description counts 3, in a
heading 2, elsewhere in the body 1, each multiplied by how rare the word is across the roster
(`ln(1 + agents / agents-using-the-word)`). Naming an agent's codename in the task, written `@name` or in capitals (`CIPHER`), adds 10;
the ordinary word ("stream the data") does not. The reply repeats at most the first 200
characters of the task.
There are no embeddings and no hand-kept keyword list, so the ranking follows the definition
files and nothing else.

## Tests

```bash
python -m unittest discover -s mcp_server/tests -t .
```

71 tests, standard library only: 24 for the registry (including the real 40-agent roster),
36 for the JSON-RPC server in-process, and 11 end-to-end tests that start
`python -m mcp_server` as a child process and exchange real JSON-RPC messages with it over
stdio. The tests read the definition files and write only to temporary directories.

## Relation to `sigma-agents`

A separate, older server (`agents-mcp-server`, TypeScript on the official MCP SDK, in its own
repository) exposes the same four tool names under the server name `sigma-agents`. It cannot
be checked from this repository; the right-hand column was read from that project's
`src/index.ts` on 2026-11-12 and may have changed since. Differences that matter when choosing
between them:

| | this server | `agents-mcp-server` |
| --- | --- | --- |
| Dependencies | Python standard library | Node.js, `@modelcontextprotocol/sdk` |
| `invoke_agent` | returns the prompt, never runs a model | runs the task on a local model through the gateway when one is reachable, otherwise returns the prompt |
| `find_agent` | scores the definition files | hand-kept keyword map in the source |

The two have different server names and can be registered side by side.
